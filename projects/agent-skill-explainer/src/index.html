01 — THE PIECES

名字很像，
职责不同。

先把四块拼图
放回各自的位置。

✳

Agent 执行任务的系统

围绕目标，结合模型、指令、上下文与工具推进工作。它根据结果决定下一步：继续、修改、结束，或请你补充信息。

关键在于：不只回答，还能组织行动。
▤

Skill 可复用的工作方法

告诉 Agent 某类任务该怎么做好。可以包含说明、参考资料、模板和脚本；被读取和采用后，才会影响这次工作。

它可以指导工具使用，但不会自己决定、自己执行。
⌘

Tool 具体的操作能力

搜索网页、读取文件、运行代码、截图……每个工具接收输入、执行操作，再把结果交还给 Agent。

工具可能执行成功，也可能返回错误或不完整的结果。
◈

Model 理解与推理的能力来源

处理输入、生成内容，也可以提出工具调用。运行环境负责执行调用并返回结果；模型与这些机制一起构成 Agent 系统。

“模型”和“使用模型工作的整个系统”，不是同一层概念。

03 — A CLOSER LOOK

Skill 像一本
能随身带走的
制作手册。

把你反复强调的方法保存下来。下次遇到相似任务，Agent 可以读取它，而不必让你从头解释。

但手册不等于执行者。
Skill 不一定要用工具，也不是越长越好。
是否读取、如何应用，由 Agent 结合任务判断。

05 — CLEAR THE CONFUSION

所以，
Skill 会自己
调用工具吗？

真正调用工具的是谁？

模型可以提出工具调用，由运行环境执行；Agent 系统利用返回结果继续推进。Skill 提供指导，也可能附带可执行脚本，但它本身不是独立运行的主体。

没有 Skill，还算 Agent 吗？

可以。Agent 仍能根据目标、指令和可用工具工作。Skill 是积累专项方法的方式，并非所有 Agent 的必要组成。

一段 Prompt 就是 Skill 吗？

Prompt 是给模型的输入。Skill 把特定任务的方法组织成可发现、可复用的说明与资源。它可以以提示文本为核心，但通常还包括适用场景与输出约定。

需要一开始就做很多 Agent 吗？

不需要。先让一个 Agent 配合少量技能完成真实任务。只有出现明确分工、上下文隔离或并行需求时，再考虑多个 Agent。

你给目标。
Agent 把工作推进下去。

Skill 帮它沿用好方法。Tool 让它有能力动手。
